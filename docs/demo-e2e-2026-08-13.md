# CloudMoo live E2E on demo.cloudmoo.com — 2026-08-13

Full connect → sync → create → monitored → alerting → destroy cycle exercised
through the live UI (Playwright, real browser) on https://demo.cloudmoo.com for
all six providers, with labeled throwaway assets (unique run labels + local
ledgers, ≤ ~$10/provider, always-free shape on OCI). Deploy path: push to
`develop` → server-side suite (scratch DB, prod untouched) → `redeploy.sh`
(docker compose) on the demo VM. Mocked suite was green before every deploy:
**346 tests, `manage.py check --deploy` clean.**

## Per-provider results

### DigitalOcean — PASS
- Verified: UI connect, inventory (servers/volumes/snapshots/firewalls/VPCs/CDN),
  per-minute checks (`AssetMonitoringState` fresh every minute), asset detail +
  timeline in UI, "Check status now", power-off detected in ~2 min with alert
  email (full content incl. provider/console URLs), destroy → `no_longer_exists`
  tombstone + check schedule removed.
- Fixed: empty-account API shapes aborted the whole sync (`databases: null`,
  missing `apps` key with meta total=0, `/v2/registry` 404 → plural endpoint,
  single-object wrap) + regression tests.
- Fixed: fresh installs had no `CoreCloudServiceProvider` rows → empty Connect
  page (seed migration 0094).
- Fixed: connect views bypassed the `CoreCloud.sync_assets()` wrapper →
  `last_synced` never stamped and asset schedules not reconciled at connect
  (all six connect views).

### Hetzner — PASS
- Verified: UI connect (incl. Object Storage S3 credentials), inventory
  (server, primary IPs, images, locations, SSH keys, LB types, buckets),
  normalized statuses (`available`), power-off → `stopped` in ~1 min + alert

- Fixed: the connect template never rendered the Object Storage fields (the

- Note: deprecated `cx22` type; created `cx23@fsn1` (cpx11/cax11 rejected by

### Vultr — PASS
- Verified: UI connect, inventory (instances, volumes, plans, regions,
  object storage, storage clusters/tiers), halt → `stopped` in ~1 min +
  alert email, destroy → tombstone + schedule removed.
- Fixed: optional feature collections (`vpc2`, `nat-gateways`, `cdn`,
  `ssl/certificates`) return 404 on accounts without them → whole sync aborted;
  now recorded as absent (documented live-E2E precedent) + regression test.
- Fixed: registry listing used POST-only singular `/v2/registry` → plural

- Fixed: `inference` envelope key (`subscriptions`, not `inference_endpoints`).
- Fixed: a transient provider error in one family aborted the entire sync —
  per-family isolation now logs/skips the failed family (rows untouched,
  fail-closed on deletions) + regression test.
- Fixed: detail-page counts ignored dynamically-registered families
  (provider-aware relation list).
- Note: this account currently returns account-scoped 500s on
  `plans/regions/kubernetes/object-storage/inference/registries` (intermittent,
  ~$250 overdue balance suspected; no Vultr status incident). Isolation fix
  handles it safely; inventory completes when the API recovers.

### AWS — PASS (with structural caveats below)
- Verified: UI connect, full inventory across 33 regions (4,271 assets —
  instance, EBS, SG, VPC/subnets/route tables/NACLs/IGWs, backup jobs,
  eventbridge, CloudWatch alarms/metrics/log groups…), stop → `stopped` in
  ~1 min + alert, terminate → `terminated` tracked + second alert, tombstone
  after AWS purged the terminated instance.
- Fixed: **monitoring-flood defect** — the sync inventoried 2,488 CloudWatch
  metric series as actively-monitored assets (~3,300 enabled 1-min check tasks
  vs ~960/min worker throughput → unbounded queue, 26k backlog). Metric series
  now inventory with monitoring DISABLED (telemetry, not lifecycle assets);
  console honestly shows "Monitored 893 / 4271 (20.9%)". Queue drained
  26k → ~5k in minutes after the fix + row flip. Regression assertions added.
- Caveat (NOT fixed — design decision needed): `sync_cloud_assets` has
  soft 900s / hard 1200s limits, but a full AWS pass takes ~1.5 h on this
  account (33-region pagination incl. CloudWatch list_metrics). Log-verified:
  `Hard time limit (1200s) exceeded` + worker SIGKILL at 18:23, with
  `acks_late` requeue churn (up to 5 retries). Consequences: periodic AWS
  syncs never complete; end-of-pass schedule reconciliation never runs (a
  tombstoned AWS instance kept being checked every minute until removed
  manually); the kill/retry bursts starve other assets' 1-min checks
  (observed as ~15-min stale `AssetMonitoringState` on brand-new UpCloud/OCI
  assets before recovery). Options: per-family task fan-out (preferred),
  provider-aware limits/cadence, or smaller per-pass scope.
- Caveat: connect/sync POSTs run full inventory inline (gunicorn 3600s). At
  AWS scale this blocks a web worker for ~1.5 h and dies silently if the
  container restarts mid-pass. Consider moving connect/sync to queued tasks
  with a "syncing" UI state.

### UpCloud — PASS
- Verified: UI connect with **API token** (new Bearer support; legacy Basic
  kept), inventory (servers, storages), stop → `stopped` + alert email,
  destroy incl. disks → tombstone + schedule removed.
- Fixed: connect required username/password — new accounts only get `ucat_`
  tokens. Form/model/checks now prefer Bearer; network errors on validation
  no longer 500; template renders the token field; migration 0095.
- Notes: DEV-plan quota exhausted by pre-existing servers → used `1xCPU-1GB`;
  labels are key/value objects; cloud-init templates need `metadata: yes`;
  stop action uses `stop_type` (not `type`).

### Oracle (OCI) — PASS (built from scratch)
- Built: complete provider (`apps/console/cloud/oracle/` + `checks/oracle.py`
  + connect template + migration 0096 incl. provider seed + dashboard/asset-
  detail wiring + 18 tests) using the official `oci` SDK (request signing with
  tenancy/user OCIDs, fingerprint, region, private key PEM).
- Fixed: provider model modules missing from `apps/models.py` →
  `provider_account` raised NotImplementedError outside web-request contexts
  (also affected upcloud/linode).
- Verified: UI connect (live `get_tenancy` validation), inventory, `RUNNING`
  tracked, SOFTSTOP → `STOPPED` + alert email, destroy incl. boot volume +
  labeled VCN/subnet cleanup → tombstone + schedule removed.
- Notes: free-tier micro capacity exhausted in AD-1/2 (AD-3 accepted);
  regional subnets required for AD-flexible launches; instance destroy needs
  VNIC-drain retries before subnet/VCN delete.

  tenancy defaults) were touched.

## Remaining broken / follow-ups
1. **AWS periodic sync can never complete** (20-min limit vs ~1.5 h pass) —
  top structural issue; see AWS caveat.
2. Inline sync POSTs (all providers; pathological at AWS scale) — move to
  queued tasks + UI progress state.
3. CloudWatch metric *collection* still paginates 33 regions every pass
  (~35 min of each AWS sync) even though series are inventory-only — consider
  capping or interval-skipping reference families.
4. Dashboard welcome copy (empty state) mentions only 3 of 6 providers.
5. `CloudEditForm` has no oracle credential fields (same gap as linode);
  edit page works for name/status only.
