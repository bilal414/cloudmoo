Features

Everything you need to watch your clouds

Connect your provider accounts once — CloudMoo discovers your infrastructure and keeps watching it around the clock.

Multi-cloud asset discovery

Connect provider accounts and CloudMoo imports your servers, volumes and databases automatically, keeping the inventory in sync.

Per-asset status monitoring

Uptime checks on schedules from 1-minute intervals up, configured per asset and run by an engine you control.

30-day status timeline

Every asset keeps a 30-day uptime timeline and incident log, so you can see exactly when it went down and came back.

Email alerts on changes

Status and configuration-change emails to per-asset recipient lists, delivered through your own SMTP server or any Django email backend.

Team accounts with roles

Multiple members per account with roles, so everyone on the team gets exactly the access they need.

Security built in

TOTP two-factor authentication, rate-limited login and password reset, and optional reCAPTCHA v3.

REST API with token auth

A token-authenticated REST API for automation and integrations — script your inventory instead of clicking through it.

Plan-based limits

Per-plan limits on clouds, assets and team members, ready for multi-tenant instances that serve many accounts.

How it works

Up and watching in three steps

1

Connect a cloud

Add a provider account with read-only API credentials. CloudMoo never needs write access to your infrastructure.

2

Assets auto-discovered

The sync engine imports your servers, volumes and databases, and scheduled status checks start from 1-minute intervals.

3

Get alerted by email

When an asset changes state or configuration, the right people get an email — per-asset recipient lists through your own SMTP server.

Self-hosted & open source

Your monitoring, your server, your data

CloudMoo is released under the MIT license and runs anywhere Docker runs — a VPS, a home lab, or a VM in any cloud. No AWS account required, no vendor lock-in, no per-seat pricing, no data leaving your infrastructure.

  • Your data stays with youAccounts, cloud connections, assets and uptime history live in your own PostgreSQL database.
  • MIT licensedUse it, modify it, redistribute it — commercially or otherwise.
  • No vendor lock-inThe whole stack is in the repo: Django app, monitoring engine, Docker Compose setup.
  • Optional extras, off by defaultSentry error tracking and reCAPTCHA v3 only run if you configure them.

The stack you run

  • Web appDjango console + REST API, served by gunicorn & nginx
  • DatabasePostgreSQL for accounts, assets and uptime history
  • Monitoring engineCelery worker + beat scheduler, with a RabbitMQ broker
  • EmailYour SMTP server, or any Django email backend
  • DeployEverything wired together with Docker Compose

Get started

Deploy your own CloudMoo

From a fresh clone to a running dashboard in a few minutes.

Quick start — Docker Compose

$ git clone https://github.com/bilal414/cloudmoo.git
$ cd cloudmoo
$ cp .env.example .env  # set DJANGO_SECRET_KEY
$ docker compose up --build
# dashboard on http://localhost:8000 — sign up at /signup/ or:
$ docker compose exec web python manage.py createsuperuser

One-line VPS installer

$ curl -fsSL https://raw.githubusercontent.com/bilal414/cloudmoo/main/install.sh | sudo bash

FAQ

Frequently asked questions

Is CloudMoo free?

Yes. CloudMoo is open source under the MIT license — free to use, modify and self-host, with no per-seat pricing. You only pay for the server you run it on.

Do I need an AWS account?

No. CloudMoo is fully self-hosted — the dashboard, REST API and the monitoring engine (Celery workers plus a beat scheduler) all run in the same Docker stack on your own server. AWS only appears as one of the six cloud providers you can monitor.

Which credentials does it need?

Read-only API tokens for each cloud provider — CloudMoo never needs write access. For AWS, the repo ships an example read-only IAM policy (aws-cloudmoo-readonly-policy.json) you can attach directly.

How are alerts sent?

By email, through your own infrastructure: any SMTP server works, and so does any Django email backend (Amazon SES, or the console backend for development). Recipient lists are configured per asset.

What are the minimum requirements?

A small VM is enough — 1 vCPU and 2 GB of RAM with Docker and Docker Compose installed. The Compose stack includes the web app, the monitoring worker and scheduler, PostgreSQL and RabbitMQ.

Is it multi-user?

Yes. Accounts support multiple team members with roles, and every user gets TOTP two-factor authentication, rate-limited login and optional reCAPTCHA v3 protection.
